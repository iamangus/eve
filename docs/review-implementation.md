# Eve review implementation audit

Audited against all 52 recommendations from the review of snapshot `667800b`.
Updated: 2026-10-20. Paths are relative to this repository.

## Scope and interpretation

- Recommendation 1 (application/proxy/MCP authentication) is deferred at the owner's request. No login, OIDC, or new service-authentication layer is added.
- Recommendation 3 uses the owner's revised rule: a private Matrix room has exactly two currently joined members, Eve and the configured owner. An allowlist alone never authorizes private context.
- The other 51 recommendations have corresponding implementation changes. The evidence below distinguishes code/regression coverage from external-service validation; it is not a claim that every production interaction has been exercised.
- Existing persistent-run history, steering, and the single final-message writer are preserved. Histories are not rebuilt every turn.

## Validation performed

- `GOTOOLCHAIN=go1.26.9 make check`: passed. Includes frontend production build, Go race tests across all packages, 2 frontend unit tests, 6 Playwright browser tests, vet, npm audit, and govulncheck.
- npm audit: no reported vulnerabilities.
- govulncheck: no reachable or imported-package vulnerabilities; one advisory remains in an unused portion of a required module. This is not reported as a vulnerable executed path.
- Real compiled Eve process: `scripts/smoke_restore.py` passed. Exercises a fresh data directory, exclusive process lock, durable notification, offline owner-input acceptance, graceful shutdown, full stopped-directory copy/restore, account recovery, and preserved deduplication.
- Mock SMTP/CalDAV/Matrix tests do not require the owner's credentials or mutate external systems.

## Explicit validation limits

- Docker is not installed in this environment. Docker startup/volume/restore checks exist in CI but were not executed locally.
- No live owner IMAP/SMTP, Matrix homeserver/E2EE, CalDAV account, or AgentFoundry/Temporal service was exercised. The code and mock contracts are tested; production interoperability is not assumed.
- SMTP cannot provide exactly-once recipient delivery after an uncertain remote acknowledgement. Stable Message-ID and surfaced ambiguity are the intentional supported behavior.
- Automatic deletion of retained Matrix keys/replay state is deliberately not implemented because it would weaken replay protection or make history undecryptable. Storage growth and protected backups are documented.
- Authentication remains deferred. None of these changes make an unauthenticated public deployment appropriate.
